## 3. 目标

`7.8B` 的目标不是再加新节点或新内容，而是把已经接通的 `8` 层结构调到可签署。

完成标准：

1. `8` 层 run 的 dedicated evidence 稳定存在。
2. `5-6 / 7-8` pair 不再是“有结构、无满足”。
3. Normal / Hard 不再明显过稳。
4. Nightmare 不再在中段断裂，至少能稳定进入 late-game 评估区间。
5. `7.8` 阶段文档可以从 `Long-run Tuning Follow-up Required` 升级为正式关闭态。

---

## 4. 调优范围

### 4.1 允许调整

1. floor scaling
2. enemy density / elite density
3. merchant cadence
4. guaranteed node cadence
5. reward curve / fallback source 权重
6. late-floor loot / event / challenge pressure

### 4.2 不在本轮处理

1. 新增第 `9~10` 层 story floor
2. 再新增新的中期节点类型
3. 新增 Boss 内容批次
4. 新的资源生产

---

## 5. 具体补救方向

### 5.1 Reward Curve

1. 提高 `5-6 / 7-8` 的独立 reward 权重和 pair satisfaction。
2. 检查 `pair fallback` 是否在 8-floor 结构中仍然过晚或过弱。
3. 复核 `merchant / guaranteed node / challenge reward` 对 late-game pair 的覆盖率。

### 5.2 Pacing

1. 降低 Normal / Hard 的过稳倾向，避免 `8` 层被“白送通关”。
2. Nightmare 则相反，需要把中段断裂改成“能进入 late-game 再失败”。
3. 调优必须区分：
   - `story topology correctness`
   - `difficulty quality`

### 5.3 Simulator / Report

1. 继续保留 `Phase 6` 的 `5` 层基线冻结，不允许 `7.8B` 破坏旧 evidence。
2. 所有 long-run 结论只看 dedicated `8-floor` evidence。
3. 如需新增 scenario override，必须按 `7.2` governance 流程走 calibration 备案。
