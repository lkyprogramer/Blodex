## 4. Representative Samples

### 4.1 rare-weapon-upgrade

- 目标：代表性 rare 武器升级必须被识别成 `accepted + major`
- 用途：约束 `boss reward / fallback / compare` 不要把明显升级判成 sidegrade

### 4.2 build-threshold-offense-pivot

- 目标：带 key item 与 pivot 的 build threshold 形成时，必须被识别成 contract spike
- 用途：约束 build-formed 反馈与 spike 统计一致

### 4.3 boss-reward-sequential-medium-upgrade

- 目标：Boss 多件奖励必须逐件按更新后的玩家状态评分
- 用途：约束 runtime 与 simulator 保持 sequential baseline 一致

## 5. 治理规则

1. 如果 sample 失败，先判断：
   - runtime bug
   - model incomplete
   - sampling mismatch
   - content drift
2. 只有确认不是 `runtime bug`，才允许改 calibration。
3. 调整 accepted/major 阈值时，必须同时说明：
   - 哪个 representative sample 被重新解释
   - 会不会影响 `PowerSpikeBudget` 保底行为
