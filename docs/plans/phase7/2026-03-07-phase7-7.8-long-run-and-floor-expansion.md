## 1. 阶段目标

把当前 `5` 层短 run 扩展为 `8~10` 层，并加入中期节点，使更长线构筑真正成立。

完成标准：

1. 楼层从 `5` 扩展到 `8~10`
2. 中期节点成立
3. pacing model 与 reward curve 重新平衡
4. save snapshot 与 summary 模型适配更长 run

### 1.1 实际完成结果

本阶段已完成并通过自动化验证，当前实现为：

1. `story run` 从 `5` 层扩展到 `8` 层，boss floor 移到第 `8` 层。
2. 分叉楼层扩展为第 `2` 层与第 `6` 层。
3. 中期节点已落地：
   - 第 `3` 层保底 `forge_anvil`
   - 第 `5` 层保底 `gambler_cache`
   - 第 `7` 层保底 `challenge room`
   - 第 `2 / 4 / 7` 层保底 `merchant`
4. `save / summary / recommendation` 已适配更长 run：
   - `RunSummary.storyMaxFloor`
   - `RunOutcomeAnalyzer` 晚期楼层阈值改为按 `storyMaxFloor` 推导
   - `RunSummaryScreen` 显示为 `floorReached / storyMaxFloor`
5. `power spike budget` 已扩展为 `8` 层 story reward curve：
   - `1-2`
   - `3-4`
   - `5-6`
   - `7-8`
6. `Phase 6` 基线已显式钉回 `5` 层：
   - simulator 继续按 `5` 层基线运行
   - evidence / pacing / report 不受 `7.8` 的 `8` 层 story run 扩展影响
7. `7.8` 新增 dedicated `8` 层 automation evidence：
   - heuristic `8` 层 report
   - real `8` 层 report
   - `pair satisfaction` 覆盖到 `5-6 / 7-8`
8. `jumpFloor()` 已恢复 endless 白盒验证能力，可直接跳到 `9+` 层。
9. dedicated tuning follow-up 已拆到 `docs/plans/phase7/2026-03-09-phase7-7.8b-long-run-tuning-closure.md`，不再把 long-run 质量收口混在本阶段完成态里。
