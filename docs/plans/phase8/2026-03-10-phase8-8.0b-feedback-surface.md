# Phase 8 - 8.0B Feedback Surface

**阶段**: `8.0B`  
**优先级**: `P0`  
**对应问题**: `8.0A` 已经建立主动规避与位移闭环，但玩家仍缺少持续、可解释、不会噪音化的反馈层；远程威胁也缺少“发射 -> 飞行 -> 命中/落空”的清晰可读性。

---

## 1. 阶段目标

把当前已有的“规则正确”兑现成“玩家看得懂、记得住、持续看得见”，并把远程威胁的反馈链从“瞬间命中”提升为“可读、可反应、可验证”。

完成标准：

1. 存在可持续观察的 Buff / Debuff HUD 图标栏。
2. ranged threat 具备 `fired / hit / miss` 的清晰事件链与表现链。
3. combat feedback 不再只依赖瞬时日志和少量浮字，而具备稳定层级与音效。
4. 元素 `Weak / Resist` 提示与当前数值模型一致，不制造虚假预期。
5. Set / Synergy 激活不再只是 toast，而是存在持续激活标记。

---

## 2. 当前问题

1. 当前主干已有瞬时反馈，但持续反馈很薄。
2. `feedbackEventRouter / SFXSystem / VFXSystem` 已有基础设施，但缺少统一阶段目标。
3. Buff / Debuff 没有独立 rail，玩家无法稳定感知当前状态。
4. 远程攻击在体验上仍接近“进入范围即瞬间结算”，玩家不容易看清自己在规避什么。
5. 元素系统已经存在，但轻微倍率差如果也显示 `Weak / Resist`，会制造错误预期。
6. 如果不先冻结 Buff rail、projectile feedback 和持久状态 indicator 的边界，`8.0B` 很容易变成“再加一层 toast”。

---

## 3. 范围与非目标

### 3.1 范围

1. ranged projectile runtime 与 `fired / hit / miss` 反馈链
2. Buff / Debuff HUD rail
3. Combat feedback 分层
4. dodge / projectile / crit / element / buff activate 的关键音效反馈
5. 元素有效性提示
6. Set / Synergy 持续激活标记

### 3.2 非目标

1. 不用更多 toast 替代持续反馈。
2. 不在本阶段重做完整 HUD 视觉风格。
3. 不在本阶段继续扩新的远程敌人内容池。
4. 不在本阶段新建大型日志/战报系统。
5. 不把 `8.0B` 扩成第二批内容包。

### 3.3 资源策略

1. 详细资源生成要求见：
   - `docs/plans/phase8/2026-03-10-phase8-resource-generation-plan.md`
2. `8.0B` 存在两条正式资源线：
   - projectile feedback
   - HUD/status feedback
3. 任何美术资源实际生成前，必须先主动向用户索取 Gemini Key。

---

## 4. 内部优先级

执行顺序固定为：

1. `P0` Projectile Runtime + `fired / hit / miss` feedback
2. `P0` Buff / Debuff HUD rail
3. `P0` Combat feedback 分层 + 关键 SFX
4. `P1` 元素克制/抗性提示
5. `P1` Set / Synergy 持续激活标记

原因：

1. `8.0A` 之后，玩家首先需要知道“自己在规避什么”，因此 projectile readability 要先落地。
2. Buff rail 和 combat feedback 共同组成持续体感的第一层。
3. 元素与 set/synergy 的收益，要建立在基础反馈已经稳定的前提下。

---

## 5. 技术方案

### 5.1 Projectile Threat Readability 冻结

`8.0B` 把远程攻击的可读性冻结为以下口径：

1. 远程攻击不再只表现为即时伤害结算。
2. 远程怪首版通过显式 `attackType: "ranged"` 走 projectile runtime。
3. projectile 瞄准“发射时玩家位置”，不是追踪弹。
4. 首版只要求支持：
   - 直线飞行
   - 固定飞行速度
   - 到点命中或落空
5. 命中分类冻结为：
   - `combat:projectile_fired`
   - `combat:projectile_hit`
   - `combat:projectile_miss`
6. 首版允许用 Phaser Graphics / tint / tween 做 placeholder VFX，不强制等待正式美术资源。

这样定义的原因是：

1. `8.0A` 已经解决“玩家可以主动 dodge”
2. `8.0B` 要解决“玩家能不能看清要 dodge 的威胁”

### 5.2 Buff Rail 布局冻结

首版固定规则：

1. 默认最多显示 `6` 个图标位
2. 超出部分显示为 `+N`
3. 排序优先级：
   - Debuff
   - 生存 Buff
   - 输出 Buff
   - 工具/功能 Buff
4. 同类内部按剩余时间从短到长排序
5. 首版禁止：
   - 第二排图标
   - 横向滚动条
   - 无限展开
6. 当前首版状态分类冻结如下：
   - `frost_slow` -> `Debuff`
   - `war_cry` -> `输出`
   - `guaranteed_crit` -> `输出`
   - `frenzy_tonic` -> `输出`
   - `phantom_brew` -> `工具`

### 5.3 Combat Feedback 分层

本阶段必须明确区分：

1. 普通命中
2. 暴击
3. 闪避/规避
4. projectile 发射
5. projectile 落空
6. Block / Guard（当前未实现，`8.0B` 仅预留分类枚举，不实际处理）
7. 元素有效命中

区分维度至少包括：

1. 浮字颜色
2. 字重/字号
3. 持续时间
4. 对应 VFX
5. 对应 SFX

### 5.4 关键音效反馈

最小音效集合：

1. projectile 发射
2. projectile 落空
3. dodge 成功
4. crit 命中
5. 元素弱点命中
6. buff activate

要求：

1. 不重复引入第二套反馈路由
2. 继续通过 `feedbackEventRouter + SFXSystem + VFXSystem` 扩展
3. projectile fire / miss 允许首版先用 placeholder cue，占位也必须先登记清单

### 5.5 元素反馈阈值冻结

基于当前 `enemyProfiles.ts` 中仍有 `+6% / -6%` 的保守倍率：

1. `damageProfile[type] >= 1.10` 才显示 `Weak`
2. `damageProfile[type] <= 0.85` 才显示 `Resist`
3. 其余轻微修正只生效数值，不显示标签

这条规则在 `8.0B` 冻结，不在 UI 层随意放大措辞。

### 5.6 Set / Synergy 持续激活标记

要求：

1. 显示当前套装层数
2. 显示 synergy 已激活状态
3. 不重复依赖瞬时 toast 作为唯一反馈
4. HUD 放置策略在 `8.0B` 冻结为：
   - `Set / Synergy` 标记不占用 Buff rail 的 `6` 个状态位
   - 作为独立于 Buff rail 的 persistent indicator 区域存在
   - 其职责是表达“当前 build 已激活的长期状态”，不是重复显示短时 Buff 剩余时间

### 5.7 架构放置建议

1. projectile runtime 优先新增 `ProjectileRuntime / ProjectileSystem`
2. projectile 事件仍通过 `feedbackEventRouter + SFXSystem + VFXSystem` 统一消费
3. Buff rail 优先新增 `HudBuffController / HudStatusRailPresenter`
4. 元素提示在 combat / projectile event metadata 上补“有效性分类”，避免 UI 再重复计算
5. set/synergy persistent indicator 放在 HUD/controller 层，不回流 `HudContainer`

## 7. 验证方案

### 7.1 自动化

1. projectile travel time 测试
2. projectile hit / miss 测试
3. Buff rail 渲染与倒计时测试
4. feedback 分类测试
5. 元素阈值显示测试
6. set/synergy indicator 测试

### 7.2 浏览器白盒

1. 用远程怪触发 projectile 发射
2. 通过移动或 dodge 让 projectile 落空
3. 使用 `frenzy_tonic`
4. 触发 `war_cry / frost_slow / guaranteed_crit`
5. 命中弱点 / 抗性目标
6. 观察：
   - 是否能看见 projectile 的发射、飞行和命中/落空
   - Buff rail 是否稳定显示
   - `Weak/Resist` 是否只在阈值场景出现
   - dodge/crit/buff activate 是否有明确 SFX/VFX

---

## 8. 出口门禁

1. 玩家能持续看到关键 Buff / Debuff。
2. ranged threat 的 `fired / hit / miss` 具有玩家可见反馈。
3. 元素反馈与当前倍率模型一致。
4. Set / Synergy 激活是持续可见状态，不是只有 toast。
5. 关键反馈不会只停留在瞬时 toast。

---

## 9. 风险与止损

1. 风险：HUD 变成状态噪音墙。  
   止损：严格执行 `6` 位 + `+N` + 固定排序规则。
2. 风险：projectile runtime 反而变成第二套战斗结算系统。  
   止损：事件路由、命中分类、SFX/VFX 继续复用现有反馈总线。
3. 风险：轻微元素修正被过度表达。  
   止损：阈值冻结，`8.0B` 不随意显示 `Weak / Resist`。
4. 风险：反馈做成更多 toast。  
   止损：持续状态栏和 combat/projectile feedback 为主，toast 只是补充。

---

## 10. 与 8.0C 交接

进入 `8.0C` 前必须确认：

1. 玩家已经能理解当前 build / buff / element 状态；
2. 玩家已经能看清远程威胁为何命中或落空；
3. 节奏节点设计不需要再承担“解释玩家状态”的责任；
4. Pacing Pass 可以专注于情绪结构而不是补反馈洞。
