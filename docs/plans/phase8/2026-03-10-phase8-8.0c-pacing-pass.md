# Phase 8 - 8.0C Pacing Pass

**阶段**: `8.0C`  
**优先级**: `P1`  
**对应问题**: 当前 `8-floor` 拓扑已存在，但准备、休整、蓄势、高潮的情绪结构还不够强。

---

## 1. 阶段目标

把现有 `8-floor` 拓扑从“节点存在”提升为“情绪结构清晰”。

完成标准：

1. 至少形成两处清晰的准备/休整窗口。
2. Boss 前后的节奏体验与普通楼层明显不同。
3. `8-floor` run 更像一段有起伏的旅程，而不是更长的线性刷层。

---

## 2. 当前问题

1. 当前 `merchant / forge / gamble / challenge` 已存在，但玩家未必能明确感到它们的情绪功能。
2. Boss 前后缺少足够强的“准备 -> 决战 -> 休整”段落感。
3. 如果不先冻结“准备室/休整窗口”的语义，后续实现很容易再次走向“继续加一层”。

---

## 3. 范围与非目标

### 3.1 范围

1. 中段准备/整理窗口
2. 最终 Boss 前准备窗口
3. 现有 merchant / forge / gamble / challenge 的情绪功能强化
4. floor-level pacing evidence 更新

### 3.2 非目标

1. 不继续增加 story floor 数。
2. 不通过再加更多节点种类替代节奏设计。
3. 不在本阶段重做 long-run tuning 的数值模型。
4. 不在本阶段新增新的大型内容池。
5. 不把 `floor 8` story finale 之后的“Boss 后休整节点”列为 story mode 首版必做项。

### 3.3 资源策略

1. 详细资源生成要求见：
   - `docs/plans/phase8/2026-03-10-phase8-resource-generation-plan.md`
2. `8.0C` 的节点与过场资源视为正式阶段需求。
3. 任何新增美术资源实际生成前，必须先主动向用户索取 Gemini Key。

---

## 4. 技术方案

### 4.1 节奏节点语义冻结

本阶段默认采用以下实现口径：

1. 准备室/休整窗口是**现有 8 层拓扑内的非战斗节点或保底房间语义**
2. 不通过新增 story floor 来实现准备室
3. 准备室最低要求：
   - 无普通怪物生成
   - 不保留上一段战斗的自动攻击锁定
   - 允许玩家补给、整理 build、确认目标
4. 当前 story topology 的最终 Boss 位于 `floor 8`，不是 `floor 5`
5. `8.0C` 首版按“单一最终 Boss 在 floor 8”冻结，不假定存在 `floor 5` mid-boss
6. 因为 story run 在 `floor 8` Boss 后结束，`8.0C` 首版不把“Boss 后休整节点”列为 story mode 必做项
7. 如需恢复“Boss 后休整”，必须以后续存在：
   - post-boss continuation
   - mid-boss floor
   为前提单独立项

### 4.2 准备窗口设计

首版目标：

1. `4 -> 5`：中段准备/整理窗口
2. `7 -> 8`：最终 Boss 前准备窗口

准备窗口至少满足：

1. 节奏减速
2. 怪物密度显著低于战斗层
3. 至少一个明确的 build/service 节点

### 4.3 Story Finale 收束设计

由于当前 story run 在 `floor 8` Boss 后结束，`8.0C` 首版的“收束”不通过 Boss 后再开一个 story 节点实现，而是通过：

1. `7 -> 8` 最终 Boss 前准备窗口强化决战前的蓄势
2. Boss 胜利后的 reward / compare / summary 承接强化
3. 最终结算前补足“读取 build 变化与结束感”的收束表现

也就是说，`8.0C` 首版优先做：

1. Boss 前准备
2. Boss 后结算收束

而不是额外插入 `floor 9` 或 story 内 Boss 后休整层。

### 4.4 现有节点的情绪功能强化

不新增更多节点种类，优先强化现有节点：

1. merchant：
   - 进入时自动暂停自动攻击锁定
   - 切换为低压背景/音效层
   - 强化“补给与整理”感
2. forge：
   - 显示当前 build 摘要
   - 给出“推荐强化方向”提示
   - 强化“build 推进”而不是纯功能点
3. gamble：
   - 显示风险预览
   - 明确“你可能获得什么 / 付出什么”
   - 强化赌局感
4. challenge：
   - 进入前显示难度预告
   - 预告关键怪物 affix 或压力来源
   - 强化“节奏升压”的心理准备

### 4.5 架构放置建议

1. 节奏节点与楼层编排继续落在 `scenes/dungeon/world/` 与 `storyRun` 相关配置
2. 不把准备室/休整节点逻辑散进 `DungeonScene`
3. evidence 更新继续通过 `phase7:long-run:evidence:report` 或后继 Phase 8 专用入口维护

## 6. 验证方案

### 6.1 自动化

1. floor-level pacing report
2. dedicated `8-floor` evidence 更新
3. 节点存在性与拓扑正确性测试

### 6.2 浏览器白盒

1. `jumpFloor(4)` 验证中段准备/整理窗口
2. `jumpFloor(7)` 验证最终 Boss 前准备窗口
3. 完成 Boss 后验证结算收束
4. 观察 merchant / forge / gamble / challenge 是否呈现不同情绪强度

---

## 7. 出口门禁

1. `8-floor` run 至少有两处清晰准备/整理窗口。
2. `7 -> 8` 的最终 Boss 前节奏与普通楼层明显不同。
3. story Boss 胜利后的结算收束明显强于当前基线。
4. 节奏强化不会破坏 `7.8B` 的 long-run evidence 基线。

---

## 8. 风险与止损

1. 风险：节奏设计退化成继续加节点。  
   止损：不以“节点数量”作为完成指标。
2. 风险：准备窗口只是空房间，没有情绪功能。  
   止损：必须满足“补给/整理/build确认”的最低语义。
3. 风险：节奏改造污染 long-run evidence。  
   止损：专门更新 floor pacing 报告并做回归核对。

---

## 9. 与 8.1 交接

进入 `8.1` 前必须确认：

1. battle / build / pacing 三条主线玩家都能持续感知；
2. 内容扩展不再承担“填补节奏空洞”的职责；
3. 第二批内容可以建立在已经稳定的节奏结构上。
