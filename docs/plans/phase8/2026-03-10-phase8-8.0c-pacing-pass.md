# Phase 8 - 8.0C Pacing Pass

**阶段**: `8.0C`  
**优先级**: `P1`  
**对应问题**: 当前 `8-floor` 拓扑已存在，但准备、休整、蓄势、高潮的情绪结构还不够强；同时怪物密度、空跑时间和环境读图也还没有形成稳定的节奏支撑。

---

## 1. 阶段目标

把现有 `8-floor` 拓扑从“节点存在”提升为“情绪结构清晰”，并压掉当前最明显的空跑感与环境重复感。

完成标准：

1. 至少形成两处清晰的准备/休整窗口。
2. Boss 前后的节奏体验与普通楼层明显不同。
3. 前中段的首次遭遇时间与走路/战斗比明显优于 `8.0A` 基线。
4. `8-floor` run 更像一段有起伏的旅程，而不是更长的线性刷层。

---

## 2. 当前问题

1. 当前 `merchant / forge / gamble / challenge` 已存在，但玩家未必能明确感到它们的情绪功能。
2. 前中段怪物分布偏散，存在“走很久才开打”的空跑感。
3. Boss 前后缺少足够强的“准备 -> 决战 -> 收束”段落感。
4. 墙壁未启用、地面变体太少，导致空间识别度和楼层差异感都偏弱。
5. 如果不先冻结“准备窗口 / 密度曲线 / 环境读图”的边界，后续实现很容易再次走向“继续加一层”或“直接上模板系统”。

---

## 3. 范围与非目标

### 3.1 范围

1. 怪物密度与遭遇分布调优
2. 中段准备/整理窗口
3. 最终 Boss 前准备窗口
4. 现有 merchant / forge / gamble / challenge 的情绪功能强化
5. 环境读图强化：
   - 墙壁启用
   - 地面变体
   - prep/recovery 节点视觉差异
6. floor-level pacing evidence 更新

### 3.2 非目标

1. 不继续增加 story floor 数。
2. 不通过再加更多节点种类替代节奏设计。
3. 不在本阶段重做 long-run tuning 的数值模型。
4. 不在本阶段新增新的大型内容池。
5. 不在本阶段直接上完整 room template / prop system。
6. 不把 `floor 8` story finale 之后的“Boss 后休整节点”列为 story mode 首版必做项。

### 3.3 资源策略

1. 详细资源生成要求见：
   - `docs/plans/phase8/2026-03-10-phase8-resource-generation-plan.md`
2. `8.0C` 的资源分两类：
   - 可直接复用的环境资产（如现有 wall）
   - 必须冻结的新环境读图资源（如 floor variants、prep/recovery nodes）
3. 任何新增美术资源实际生成前，必须先主动向用户索取 Gemini Key。

---

## 4. 技术方案

### 4.1 Encounter Density 冻结

`8.0C` 首版把怪物密度问题冻结为“节奏问题”，而不是“内容数量问题”。

首版建议口径：

1. `floor 1 ~ 4` 的怪物数整体上调
2. `MonsterSpawnSystem` 的首版参数建议：
   - `minDist = 4`
   - `maxDist = 30` 或等价放宽
   - `minSpacing = 2.0`
3. 允许引入轻量怪物群权重，但不引入完整模板系统
4. `4 -> 5` 与 `7 -> 8` 的准备窗口显著降密度

本阶段不追求“每个房间都有固定编排”，而是先把：

1. 空跑时间压下去
2. 高压层与低压层的密度差做出来

### 4.2 节奏节点语义冻结

本阶段默认采用以下实现口径：

1. 准备室/休整窗口是**现有 8 层拓扑内的非战斗节点或保底房间语义**
2. 不通过新增 story floor 来实现准备室
3. 准备室最低要求：
   - 无普通怪物生成
   - 不保留上一段战斗的自动攻击锁定
   - 允许玩家补给、整理 build、确认目标
4. 当前 story topology 的最终 Boss 位于 `floor 8`
5. `8.0C` 首版按“单一最终 Boss 在 floor 8”冻结，不假定存在 `floor 5` mid-boss
6. 因为 story run 在 `floor 8` Boss 后结束，`8.0C` 首版不把“Boss 后休整节点”列为 story mode 必做项

### 4.3 准备窗口设计

首版目标：

1. `4 -> 5`：中段准备/整理窗口
2. `7 -> 8`：最终 Boss 前准备窗口

准备窗口至少满足：

1. 节奏减速
2. 怪物密度显著低于战斗层
3. 至少一个明确的 build/service 节点
4. 有可感知的视觉差异，不只是“更空”

### 4.4 Story Finale 收束设计

由于当前 story run 在 `floor 8` Boss 后结束，`8.0C` 首版的“收束”不通过 Boss 后再开一个 story 节点实现，而是通过：

1. `7 -> 8` 最终 Boss 前准备窗口强化决战前的蓄势
2. Boss 胜利后的 reward / compare / summary 承接强化
3. 最终结算前补足“读取 build 变化与结束感”的收束表现

### 4.5 现有节点的情绪功能强化

不新增更多节点种类，优先强化现有节点：

1. merchant：
   - 进入时自动暂停自动攻击锁定
   - 切换为低压背景/音效层
   - 强化“补给与整理”感
2. forge：
   - 显示当前 build 摘要
   - 给出“推荐强化方向”提示
   - 强化“build 推进”而不是纯功能点
3. gamble：
   - 显示风险预览
   - 明确“你可能获得什么 / 付出什么”
   - 强化赌局感
4. challenge：
   - 进入前显示难度预告
   - 预告关键怪物 affix 或压力来源
   - 强化“节奏升压”的心理准备

### 4.6 Environment Readability

本阶段不做完整环境内容扩展，但必须做最低限度的空间读图强化：

1. 启用现有各 biome 的 `wall_01`
2. 引入每 biome 的 `floor_02 / floor_03 / crack_01` 变体轮换
3. prep / recovery 节点使用专用 `node_marker / panel / card`
4. 允许首版用 tint / overlay / decal graphics 做部分 placeholder

边界冻结：

1. `8.0C` 不做完整 prop system
2. `8.0C` 不做完整 room template system
3. 这两项后置到 `8.1`

### 4.7 架构放置建议

1. 节奏节点与楼层编排继续落在 `scenes/dungeon/world/` 与 `storyRun` 相关配置
2. 不把准备室/休整节点逻辑散进 `DungeonScene`
3. encounter density tuning 继续落在 `floorScaling / MonsterSpawnSystem`
4. environment readability 优先在 `RenderSystem` 与资源清单层处理
5. evidence 更新继续通过 `phase7:long-run:evidence:report` 或后继 Phase 8 专用入口维护

## 6. 验证方案

### 6.1 自动化

1. floor-level pacing report
2. dedicated `8-floor` evidence 更新
3. 节点存在性与拓扑正确性测试
4. 首次遭遇时间 / 走路时间 / 战斗时间统计
5. floor variant / wall rendering 的基础快照验证

### 6.2 浏览器白盒

1. `jumpFloor(1)` 验证前期空跑是否明显下降
2. `jumpFloor(4)` 验证中段准备/整理窗口
3. `jumpFloor(7)` 验证最终 Boss 前准备窗口
4. 完成 Boss 后验证结算收束
5. 观察 merchant / forge / gamble / challenge 是否呈现不同情绪强度
6. 观察墙壁、地面变体和 prep/recovery 节点是否带来空间识别差异

---

## 7. 出口门禁

1. `8-floor` run 至少有两处清晰准备/整理窗口。
2. `7 -> 8` 的最终 Boss 前节奏与普通楼层明显不同。
3. 前中段空跑感明显下降，Floor 1 不再频繁出现长时间无遭遇。
4. story Boss 胜利后的结算收束明显强于当前基线。
5. 环境读图强化不会破坏 `7.8B` 的 long-run evidence 基线。

---

## 8. 风险与止损

1. 风险：节奏设计退化成继续加节点。  
   止损：不以“节点数量”作为完成指标。
2. 风险：准备窗口只是空房间，没有情绪功能。  
   止损：必须满足“补给/整理/build确认”的最低语义。
3. 风险：为了压空跑感，直接把 `8.0C` 做成模板系统。  
   止损：完整模板与装饰物系统明确后置到 `8.1`。
4. 风险：节奏改造污染 long-run evidence。  
   止损：专门更新 floor pacing 报告并做回归核对。

---

## 9. 与 8.1 交接

进入 `8.1` 前必须确认：

1. battle / build / pacing 三条主线玩家都能持续感知；
2. 内容扩展不再承担“填补节奏空洞”的职责；
3. room template / props 不再承担“修补基础空跑与读图”的责任，而是建立在已经稳定的密度与环境基线上。
