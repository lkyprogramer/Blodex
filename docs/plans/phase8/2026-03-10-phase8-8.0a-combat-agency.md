# Phase 8 - 8.0A Combat Agency

**阶段**: `8.0A`  
**优先级**: `P0`  
**对应问题**: 当前战斗仍以 `click-to-move + 自动攻击 + 技能补充` 为主，玩家缺少主动规避、位移与对 telegraph 的强反馈响应能力。

---

## 1. 阶段目标

把当前“会动、会打、会放技能”的战斗模型，提升为玩家可以明确感知主动输入价值的战斗模型。

完成标准：

1. 存在真正可用的 `dodge / roll` 主动输入链。
2. `shadow_step / rift_step / wind_dash` 等位移语义技能真实改变玩家坐标。
3. `Boss telegraph -> dodge success -> damage avoided` 闭环成立。
4. dodge 与自动攻击、点击移动、技能释放之间的优先级关系被清晰冻结，避免实现分叉。
5. 浏览器白盒与自动化都可以证明“主动规避”与“站桩挨打”有明确结果差异。

---

## 2. 当前问题

1. 当前主干没有独立的 `dodge / roll / parry` 行为。
2. 战斗里最主要的输入仍然是：
   - 目标移动
   - 路径打断
   - 技能补充
3. `shadow_step / rift_step / wind_dash` 的语义接近位移，但核心技能结算仍不改变玩家位置。
4. Boss telegraph 已存在，但“玩家主动规避 -> 完全规避伤害”的结果链还没有成立。
5. 如果不先冻结交互模型，`dodge` 很容易和当前 auto-attack / pathing 打架，最终变成“功能上存在、体验上无意义”。

### 2.1 基于 `main` 的代码现实

1. `DungeonInputRuntime` 已承担 pointer / keyboard move 与技能键绑定，但当前没有 `Space` 或 dodge replay 入口。
2. `PlayerActionModule -> CombatSystem.useSkill -> resolveSkill` 当前只产出伤害 / buff 结果，`SkillDef` 与 `SkillResolution` 还没有可供 runtime 复用的位移锚点契约。
3. `BossTelegraphPresenter` 已有 telegraph 展示，但 `BossCombatService` 在 telegraph 结算时还没有查询 dodge runtime 状态。
4. `save/savePorts.ts` 与 `dungeonSceneHostFactories.ts` 当前会持久化 `path / attackTargetId / nextPlayerAttackAt` 等战斗状态，但没有 dodge cooldown、最近一次方向与 replay 口径。

## 3. 范围与非目标

### 3.1 范围

1. dodge / roll runtime
2. dodge 输入、冷却、无敌帧、路径与目标打断逻辑
3. 位移技能真实改坐标
4. Boss telegraph 的 evade 闭环
5. dodge 最低视觉反馈

### 3.2 非目标

1. 不移除自动攻击系统。
2. 不改成完整 WASD/双摇杆战斗模型。
3. 不在本阶段引入完整 sprite-sheet 动画系统。
4. 不在本阶段大改 `MovementSystem` 的基础寻路逻辑。
5. 不在本阶段新增新的职业或大规模技能池。

### 3.3 资源策略

1. 详细资源生成要求见：
   - `docs/plans/phase8/2026-03-10-phase8-resource-generation-plan.md`
2. `8.0A` 默认不强制新增大批美术资源，允许先用现有 VFX 完成闭环。
3. 若要实际生成 `dodge` 视觉资源，必须先向用户索取 Gemini Key。

## 4. 技术方案

### 4.1 输入与方向冻结

本阶段必须严格采用以下交互定义：

1. 输入键：`Space`
2. 当下列 UI 打开时，dodge 不生效：
   - event overlay
   - compare prompt
   - 任何 blocking overlay
3. dodge 方向判定顺序：
   - 最近一次有效移动输入向量
   - `玩家 -> 鼠标当前世界坐标`
   - 最近移动方向 / 当前面朝
4. 这里的“最近一次有效移动输入向量”明确指：
   - 最近一次 `click-to-move` 的点击目标，相对于玩家当前位置的归一化方向
   - 不使用 A* 当前路径段方向，避免路径拐弯导致 dodge 方向漂移
5. 输入接线冻结为：
   - 在 `apps/game-client/src/scenes/dungeon/shell/DungeonInputRuntime.ts` 追加 `keydown-SPACE`
   - 不复用 pointer / debug hotkey / 现有技能槽位绑定

### 4.2 参数冻结

首版参数固定为：

1. 位移距离：`2` 格
2. 无敌帧：`80ms`
3. 冷却：`700ms`

这些值允许在阶段内调优，但任何调优都必须满足：

1. 能稳定规避明确 telegraph
2. 不会把战斗变成无限翻滚
3. 不会因为距离太短而变成“看起来像抖动”

### 4.3 与自动攻击 / 路径的关系

`dodge` 为高优先级输入，执行时必须：

1. 立即取消当前路径
2. 立即打断当前自动攻击动作
3. 显式清空当前 `attackTargetId`
4. 不自动恢复旧路径
5. 不自动走回原目标
6. 若同一输入帧同时收到 `dodge` 与主动技能请求，先消费 `dodge`
7. 被 `dodge` 抢占的技能请求：
   - 不进入冷却
   - 不记录 `skill_use`
   - 不写入技能相关 telemetry

这条是本阶段最重要的交互合同之一，禁止实现成“翻出去又自动走回来”。

### 4.4 与不可通行格子的关系

1. dodge 沿目标方向逐格做 walkability 检查
2. 若完整 2 格均可通行，则落到目标格
3. 若中途遇到不可通行格，则停在最后一个可通行格
4. 不允许穿墙
5. 不允许停进不可通行格
6. 若第 `1` 格即不可通行，则记为 `blocked dodge`
7. `blocked dodge` 不位移、不进入无敌帧、也不消耗冷却，只允许触发轻量失败反馈

### 4.5 位移应用口径

1. `dodge` 与技能位移都不通过向 `path` 注入伪路径节点实现。
2. 不复用 `manualMoveTarget` 作为 dodge / dash / blink 的长期状态。
3. shell 侧通过独立 helper 基于当前 `dungeon.walkable` 直接结算落点并更新 `player.position`。
4. 位移尝试发生时，无论成功还是失败，都要同步清理：
   - `path`
   - `manualMoveTarget`
   - `manualMoveTargetFailures`
   - `nextManualPathReplanAt`
5. 只有这样才能避免 `MovementSystem` 的自动重规划把玩家重新拉回旧路径。

### 4.6 位移技能改造

本阶段要让以下技能从“位移语义”变成“真实位移”：

1. `shadow_step`
2. `rift_step`
3. `wind_dash`

规则：

1. 技能位移和 dodge 一样遵循 walkability 检查
2. 位移后必须更新玩家坐标
3. 位移后的自动攻击目标策略必须与 `dodge` 口径一致：
   - 默认不自动恢复旧追击
4. 核心层设计路径在 `8.0A` 冻结为：
   - 在 `packages/core/src/contracts/types.ts` 的 `SkillDef` 中新增显式 `displacement` 描述
   - `anchor: "target"` 的技能不能由 scene 侧重复选目标，`SkillResolution` 至少要补 `primaryTargetId` 或等价字段
   - `packages/core/src/skill.ts` 负责把技能位移意图与既有伤害 / buff 结算一起透传
   - 推荐形态：
     - `displacement?: { type: "blink" | "dash", distance: number, anchor: "target" | "direction" }`
   - `core` 层负责定义“此次技能具有位移意图、位移类型、距离与锚点”
   - scene/runtime 层负责：
     - 坐标应用
     - walkability 检查
     - 动画 / VFX / SFX
     - 路径与攻击目标打断
5. `8.0A` 不采用“按 skill id 在 `PlayerActionModule` 侧特殊处理位移”的方案，避免技能行为分散和后续扩展分叉
6. 允许 `PlayerActionModule` 基于通用 `runtimeSkillDef.displacement` 或 `SkillResolution` 泛化字段接线，但禁止硬编码 `shadow_step / rift_step / wind_dash`

### 4.7 Telegraph Evade 闭环

`BossTelegraphPresenter` 已有可视化基础，本阶段要补的是：

1. telegraph 命中判定与 dodge i-frame 的关系
2. telegraph 命中失败路径
3. telegraph 成功规避路径
4. 对应的 VFX/SFX 差异
5. 判定模型在 `8.0A` 冻结为“双重判定”：
   - **位置脱出**：telegraph 结算时，玩家不在 AoE 范围内，则规避成功
   - **i-frame 生效**：telegraph 结算时，若玩家仍处于 dodge i-frame，则规避成功
6. `8.0A` 不采用“dodge i-frame 免疫所有伤害来源”的全局无敌模型
7. 非 telegraph 伤害是否可被 dodge 免疫，不在 `8.0A` 首版默认打开；只有显式标记为可 evade 的伤害来源才消费 dodge i-frame
8. 这意味着：
   - `BossCombatService` 必须查询 dodge runtime 状态
   - telegraph 命中应在结算时以实时位置与 dodge 状态共同判定
9. `BossCombatService` 不直接依赖 `DungeonScene`，而是通过 `apps/game-client/src/scenes/dungeon/encounter/ports.ts` 补只读 dodge 查询口
10. telegraph 结算结果必须冻结为可消费分类：
    - `hit`
    - `evaded_by_position`
    - `evaded_by_iframe`

### 4.8 最低视觉表现标准

本阶段不要求完整 sprite-sheet，但必须至少满足：

1. dodge 期间角色有 `tint / alpha` 变化
2. dodge 路径上存在短残影或速度拖尾
3. 落地有轻微 camera nudge
4. telegraph 规避成功时有清晰的“成功规避”提示

### 4.9 回放、保存与证据口径

1. `packages/core/src/contracts/types.ts` 的 `ReplayInputEvent` 需要新增 `dodge` 事件。
2. replay 记录的是“已解析后的 dodge 意图”，不是裸 `Space`：
   - 至少包含方向向量或等价落点
   - 标记方向来源：`move_vector / cursor / facing`
3. `RunSaveSnapshot` / restore 至少要保住：
   - dodge 剩余冷却
   - 最近一次成功方向
   - 最近一次结果分类与方向来源
4. 正在进行的 dodge tween / 残影在恢复时不强行续播，恢复口径统一回到 idle，但不能借恢复存档重置 dodge 冷却。
5. 浏览器白盒、后续 `8.0B` feedback、以及 evidence 统一消费以下事件语义：
   - `attempt`
   - `blocked`
   - `success`
   - `evade_success`

### 4.10 架构放置建议

1. `DodgeRuntime` 放在 `apps/game-client/src/scenes/dungeon/shell/`
2. `Space` 绑定与 dodge 输入仲裁落在 `apps/game-client/src/scenes/dungeon/shell/DungeonInputRuntime.ts`
3. `core` 层位移契约落在 `packages/core/src/contracts/types.ts`，解析透传落在 `packages/core/src/skill.ts`
4. 场景侧坐标应用、路径中断、VFX/SFX 通过 shell/runtime host 接入
5. telegraph evade 继续放在 `encounter/` 侧，不回流 `DungeonScene`
6. `BossCombatHost` / `BossCombatService` 的 evade 查询接口放在 `apps/game-client/src/scenes/dungeon/encounter/ports.ts`
7. 保存与恢复接口扩展放在：
   - `apps/game-client/src/scenes/dungeon/save/savePorts.ts`
   - `apps/game-client/src/scenes/dungeon/dungeonSceneHostFactories.ts`

## 6. 验证方案

### 6.1 自动化

1. `typecheck`
2. `dodge` cooldown / i-frame / replay 序列化测试
3. 恢复存档后 dodge 冷却不会被重置
4. 位移技能坐标变化与 `primaryTargetId` 一致性测试
5. telegraph evade 成功/失败测试
6. 路径与 `attackTargetId` 中断测试
7. walkability 边界测试：
   - 目标格不可通行时停在最后一个可通行格
   - 只能走 `1` 格时停在 `1` 格处
   - 第 `1` 格即被完全挡住时：
     - 不位移
     - 不进入无敌帧
     - 不消耗冷却

### 6.2 浏览器白盒

1. 进入 boss floor
2. 触发 telegraph
3. 触发 dodge
4. 验证：
   - 玩家没有自动走回原目标
   - 命中与规避结果不同
   - 控制台无 runtime error

## 7. 出口门禁

1. 玩家可以主动规避 Boss telegraph。
2. 位移技能不再只是语义描述，而是真实位移。
3. dodge 明确打断路径与自动攻击目标锁定。
4. 视觉上能看出角色正在闪避/翻滚。

---

## 8. 风险与止损

1. 风险：dodge 只是多了一个按键，没有战术价值。  
   止损：必须把 telegraph evade 闭环作为出口门禁。
2. 风险：dodge 与 auto-attack 打架，翻滚后又自动走回去。  
   止损：显式清空 `attackTargetId`，不恢复旧路径。
3. 风险：位移穿墙或卡墙。  
   止损：逐格 walkability 检查，停在最后一个可通行格。
4. 风险：replay / save 没有记录已解析方向，导致白盒复现与真实输入不一致。  
   止损：把 `dodge` 视为一等 replay 输入，记录解析后的方向来源与方向值。

进入 `8.0B` 前必须确认：

   - `attempt`
   - `blocked`
