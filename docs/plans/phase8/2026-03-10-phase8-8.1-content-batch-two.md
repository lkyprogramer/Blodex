# Phase 8 - 8.1 Content Batch Two

**阶段**: `8.1`  
**优先级**: `P2`  
**前置条件**: `8.0A / 8.0B / 8.0C` 全部完成  
**对应问题**: 只有在战斗主动性、持续反馈和节奏结构都成立后，第二批内容扩展才有持续收益。

---

## 1. 阶段目标

在 `8.0A ~ 8.0C` 完成后，开启下一批内容扩展，但必须建立在已经被玩家真实感知到的 `battle / build / pacing` 体验之上。

完成标准：

1. 第二批内容扩展不会重新掩盖主动性、反馈和节奏问题。
2. 每项新增内容都建立在已经稳定的 Phase 8 体验基线之上。
3. 内容扩展的价值来自体验深化，而不是单纯数量增加。

---

## 2. 启动前提

只有以下全部满足，才允许进入 `8.1`：

1. `8.0A` 已完成
2. `8.0B` 已完成
3. `8.0C` 已完成
4. 玩家已能持续感知：
   - 主动战斗输入
   - 持续状态反馈
   - 层间节奏差异
5. `phase8:content-gate:check` 已通过

---

## 3. 候选内容

1. 第二批 Boss
2. 更多元素/敌人画像
3. 更深的 set / item batch
4. 更强的中后段 challenge 变体

---

## 4. 范围与非目标

### 4.1 范围

1. 新内容池评估与排序
2. 与 Phase 8 体验基线对齐的内容扩展

### 4.2 非目标

1. 不在 `8.0A ~ 8.0C` 未完成前提前启动。
2. 不把“新增更多系统”当作目标本身。
3. 不重新引入 Phase 7 曾经治理过的架构债。

### 4.3 资源策略

1. 详细资源生成要求见：
   - `docs/plans/phase8/2026-03-10-phase8-resource-generation-plan.md`
2. `8.1` 的资源只允许在具体内容包被确定后冻结与生成。
3. 所有美术资源实际生成前，必须先主动向用户索取 Gemini Key。

---

## 5. 执行原则

1. 每项新增内容都必须回答：
   - 它强化的是 `battle / build / pacing` 中哪一条？
2. 不允许再回到“先堆内容，再回头修体验”的路径。
3. 内容扩展必须继续遵守：
   - `check:architecture-budget`
   - `phase8:content-gate:check`
   - `phase7:content-gate:check`
   - `phase6:evidence:check`
   - `art-style-bible`
   - `asset-plan / audio-plan / manifest` 的资源入口约束

---

## 6. 推荐 PR 拆分

本阶段不冻结具体内容包数量，但要求每个 PR 至少满足：

1. 一类内容 / 一条主链
2. 自带验证与出口门禁
3. 不混入大范围架构重构

推荐拆法：

1. `PR-8.1-01`：第二批 Boss
2. `PR-8.1-02`：元素/敌人画像扩展
3. `PR-8.1-03`：set / item batch 扩展
4. `PR-8.1-04`：中后段 challenge 变体

---

## 7. 验证方案

1. 所有内容扩展都必须保留：
   - 自动化
   - 浏览器白盒
   - 人工体验检查
2. 内容验收不只看“能不能跑”，还看：
   - 是否强化主动战斗
   - 是否增强 build 感知
   - 是否改善节奏结构

---

## 8. 出口门禁

1. 新内容建立在稳定的 Phase 8 体验基线上。
2. 没有重新回到“内容先行、体验后补”的开发模式。

---

## 9. 风险与止损

1. 风险：前三阶段没收口就急着开内容。  
   止损：`8.1` 启动前提必须全部满足。
2. 风险：内容扩展把体验问题重新掩盖。  
   止损：每个内容 PR 都要回答它服务于哪条主线。

---

## 10. 当前状态

当前阶段状态：

- `Blocked by 8.0A ~ 8.0C`
- `Not Started`

在前三阶段未完成前，不允许把 `8.1` 作为默认下一步。
