# Phase 8 - 8.1 Content Batch Two

**阶段**: `8.1`  
**优先级**: `P2`  
**前置条件**: `8.0A / 8.0B / 8.0C` 全部完成  
**对应问题**: 只有在战斗主动性、持续反馈和节奏结构都成立后，第二批内容扩展才有持续收益；房间模板、装饰物、第二批远程内容也应在这一阶段集中吸收，而不是前置打散前三个阶段。

---

## 1. 阶段目标

在 `8.0A ~ 8.0C` 完成后，开启下一批内容扩展，但必须建立在已经被玩家真实感知到的 `battle / build / pacing` 体验之上。

完成标准：

1. 第二批内容扩展不会重新掩盖主动性、反馈和节奏问题。
2. 房间模板与装饰物系统建立在已经稳定的 encounter density / environment readability 基线上。
3. 第二批远程内容建立在已经存在的 projectile runtime 与 feedback surface 之上。
4. 内容扩展的价值来自体验深化，而不是单纯数量增加。

---

## 2. 启动前提

只有以下全部满足，才允许进入 `8.1`：

1. `8.0A` 已完成
2. `8.0B` 已完成
3. `8.0C` 已完成
4. 玩家已能持续感知：
   - 主动战斗输入
   - 持续状态反馈
   - 层间节奏差异
5. `phase8:content-gate:check` 已通过

---

## 3. 候选内容

1. room template system
2. prop / decoration pack
3. second ranged content batch
4. 第二批 Boss
5. 更多元素/敌人画像
6. 更深的 set / item batch
7. 更强的中后段 challenge 变体

---

## 4. 范围与非目标

### 4.1 范围

1. room template authoring 与组装逻辑
2. prop / decoration system 与资源包
3. second ranged content batch
4. 与 Phase 8 体验基线对齐的第二批 Boss / element / item / challenge 扩展

### 4.2 非目标

1. 不在 `8.0A ~ 8.0C` 未完成前提前启动。
2. 不把“新增更多系统”当作目标本身。
3. 不重新引入 Phase 7 曾经治理过的架构债。
4. 不把 `8.1` 当作补做 `8.0B / 8.0C` 基础修复的垃圾桶。

### 4.3 资源策略

1. 详细资源生成要求见：
   - `docs/plans/phase8/2026-03-10-phase8-resource-generation-plan.md`
2. `8.1` 的资源允许冻结以下三条主线：
   - room template / props
   - second ranged content batch
   - 第二批 Boss / element / item
3. 所有美术资源实际生成前，必须先主动向用户索取 Gemini Key。
4. 未被 gameplay 与 runtime 接线明确选定的资源，不得提前大批量生成。

---

## 5. 执行原则

1. 每项新增内容都必须回答：
   - 它强化的是 `battle / build / pacing` 中哪一条？
2. 不允许再回到“先堆内容，再回头修体验”的路径。
3. `room template / props` 必须建立在 `8.0C` 已经收口的密度与环境读图基线上。
4. `second ranged content batch` 必须建立在 `8.0B` 已经存在的 projectile runtime / feedback surface 上。
5. 内容扩展必须继续遵守：
   - `check:architecture-budget`
   - `phase8:content-gate:check`
   - `phase7:content-gate:check`
   - `phase6:evidence:check`
   - `art-style-bible`
   - `asset-plan / audio-plan / manifest` 的资源入口约束

---

## 6. 子方向定义

### 6.1 Room Template System

目标：

1. 让不同房间在结构上可识别
2. 支持预设 spawn point
3. 支持房间功能差异化

首版最低要求：

1. Grand Hall / Arena / Ambush Corridor / Crossroads / Study / Vault / Bridge 等模板池
2. 模板之间不会重叠
3. 模板放置后拓扑仍连通
4. 模板房间可绑定 encounter authoring，而不要求完全替代所有随机房间

### 6.2 Props / Decoration Pack

目标：

1. 让房间不仅是矩形地面
2. 提供空间地标与视觉节奏点

首版最低要求：

1. pillar
2. brazier
3. bookshelf / altar / bone heap 等 biome props
4. 区分：
   - 纯装饰
   - 阻挡型 props

### 6.3 Second Ranged Content Batch

目标：

1. 让 projectile runtime 有更多真实内容承载
2. 不让 `8.0B` 的 projectile 只停留在基础敌人上

首版最低要求：

1. 第二批远程怪 archetype
2. 元素化 projectile 差异
3. 可扩展到：
   - 直线弹
   - 扩散弹
   - 延时落点弹

### 6.4 Boss / Element / Item Batch Two

目标：

1. 在 battle / build / pacing 三条线已稳定后扩第二批内容
2. 不重新引入“先靠内容堆满体验空洞”的开发模式

## 8. 验证方案

1. 所有内容扩展都必须保留：
   - 自动化
   - 浏览器白盒
   - 人工体验检查
2. 内容验收不只看“能不能跑”，还看：
   - 是否强化主动战斗
   - 是否增强 build 感知
   - 是否改善节奏结构
3. Room template / props 至少要补：
   - 模板不重叠测试
   - 拓扑连通测试
   - 预设 spawn point 在合法区域内的测试
4. Second ranged content batch 至少要补：
   - projectile family 行为测试
   - ranged threat readability 白盒验证

---

## 9. 出口门禁

1. 新内容建立在稳定的 Phase 8 体验基线上。
2. room template / props 不再只是视觉堆砌，而能支撑 encounter 差异。
3. second ranged content batch 不会重新引入“看不清、反应不了”的远程威胁。
4. 没有重新回到“内容先行、体验后补”的开发模式。

---

## 10. 风险与止损

1. 风险：前三阶段没收口就急着开内容。  
   止损：`8.1` 启动前提必须全部满足。
2. 风险：room template system 变成新一轮大规模 procgen 重构。  
   止损：`8.1` 首版只做模板池、放置、连通、spawn point 契约。
3. 风险：props 只是美术堆量，无法形成可辨识 encounter。  
   止损：props 与 room template / encounter authoring 一起验收。
4. 风险：第二批 ranged 内容把 `8.0B` 的 readability 问题重新带回来。  
   止损：必须建立在已有 projectile runtime / feedback surface 上扩展。

---

## 11. 当前状态

当前阶段状态：

- `Blocked by 8.0A ~ 8.0C`
- `Not Started`

在前三阶段未完成前，不允许把 `8.1` 作为默认下一步，也不允许把 room template / props 视为 `8.0C` 的隐性必做项。
